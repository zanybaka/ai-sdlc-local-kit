# Vendor contract: agent CLI integration points

The ai-task system depends on surfaces of four agent CLIs that their vendors
document partly or not at all: Claude Code, Codex, Devin and cursor-agent.
Claude Code has already drifted twice, in the limit-message format
and in the statusLine quota payload shape, which is now read by
a parser that accepts several shapes. Before this inventory such drift showed
up in the middle of a wave as silent quota blindness or failed runs. This file
indexes every external touchpoint: where the code consumes it, what drift
looks like, and which test or probe catches it.

Two detection layers live in `tests/test_vendor_contract.py`, and the backend
tests named in the tables below add to them. This kit ships no test
suite, so the test
names below say how a touchpoint is guarded, not a command you can run here:

- **Pinned-shape tests** run in the default suite. Each one holds a canonical
  fixture of a touchpoint and asserts that our parsers accept the shape the
  vendor emits today. Deeper permutation coverage stays in
  `tests/test_unit.py`, `tests/test_cli.py` and `tests/test_codex_backend.py`.
- **Live canaries** carry the marker `vendor_canary` and are skipped by
  default. They probe the installed Claude Code: the credentials chain, the
  `claude` binary and its flags, the OAuth usage endpoint with the real token,
  and the worker settings JSON. `CanaryWorkerSettingsApplied` is the one canary
  that calls the model, once, with the bundled worker argv.
  A failure message says either `VENDOR FORMAT CHANGED`, when Claude Code
  drifted and the parsers and this file need an update, or `FEATURE BROKEN`,
  when our code or the local environment is at fault. Codex, Devin and
  cursor-agent have no live canary yet. Their contract is pinned by tests that
  run a stub CLI, and the operator checks a new CLI version by hand with the
  probe named in its row.

`ai-task quota doctor` points at the canaries in its blind-mode hint.

## How code is referenced

Every row names a symbol and the module that defines it, never a line number:
line numbers drift with every edit and once pointed at a file that had become
a 27-line wrapper. Find a symbol with `grep -n '<symbol>' <module>`.

The bundled policy template is the text returned by `default_policy` in
`scripts/ai_task/policy.py`. Its `[backends.<name>]` tables carry the launch
argv of each backend. `backend_command` and `backend_input` in
`scripts/ai_task/runs.py` turn a table into the argv and the stdin of the
process, and `backend_env` in `scripts/ai_task/lifecycle.py` builds its
environment. The `limit_patterns` and `auth_patterns` of every table come from
`LIMIT_WORDS` in `scripts/ai_task/policy.py` and the auth substrings next to
it.

## In-session subagents

`claude_subagent` and `codex_subagent` launch no process, so they
have no CLI surface in this inventory. The teamlead session starts the
subagent through its own host and reports the result with
`ai-task worker-done`. Their only vendor dependency is the host's ability to
start a fresh subagent, which ai-task cannot observe.

## Ruff in the lint gate

The Stop hook `hooks/lint-gate.py` (not shipped in this kit) runs in every
repository where it is registered and edits files there, so the ruff output it reads decides which lines it may
rewrite. Ruff is not an agent CLI, but its drift has the same
shape: the gate keeps running and quietly does the wrong thing.

## When a canary fails

1. `VENDOR FORMAT CHANGED` means Claude Code drifted. Capture the new shape
   with secrets redacted, extend the parser so it keeps accepting the old
   shape, add the new shape as a pinned fixture in
   `tests/test_vendor_contract.py`, and update the table above.
2. `FEATURE BROKEN` means our code or the local environment regressed. Fix it
   like any bug. The vendor contract is unchanged, so this file stays as it
   is.
3. A skip such as "no local Claude Code" is normal on a machine without Claude
   Code. Canaries never fail because a tool is absent.

The same steps apply to a pinned test of Codex, Devin or cursor-agent that
starts failing after a CLI update: compare the new `--help` with the row,
update the template table and the stub, then this file.
